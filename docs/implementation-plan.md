## Tech stack decisions (Phase 1 output — confirm before Phase 2 if you disagree)

| Layer | Choice | Rationale |
|---|---|---|
| Language | Python 3.11+ | XGBoost, pandas, scipy, and the agent/tool code all live comfortably in one language; avoids a polyglot MVP when the hackathon clock is the binding constraint |
| API framework | FastAPI | Typed request/response models (pydantic) double as the internal schemas in §5 of the brief; async-friendly for the multi-step simulation run |
| Persistence (MVP) | SQLite via SQLAlchemy Core | Zero-ops, file-based, trivially reproducible for judges; adapter interface matches what a HANA Cloud adapter would implement (see architecture.md §2) |
| Forecasting | XGBoost, baselined against naive/seasonal-naive/moving-average/exponential smoothing | Per §7 of the brief — baselines are mandatory before XGBoost is allowed to win the argument |
| Optimization | `scipy.optimize.linprog` (HiGHS, MILP via `integrality`) | PuLP/OR-Tools/Gurobi/CPLEX are off-limits by default per the brief; scipy is a general-purpose library, not a banned optimization framework — flagged as a judgment call in model-plan.md |
| Orchestration | Hand-rolled explicit state machine, no LangGraph/CrewAI/AutoGen | The workflow is a fixed DAG with exactly one conditional edge (compliance REJECTED → replan); a framework buys nothing here and the brief rules them out by default anyway |
| LLM (sensing agent) | Not selected yet — needs your input | See "Open questions" below |
| Testing | pytest | Standard; matches §21 test categories directly |
