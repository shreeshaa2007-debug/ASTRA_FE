## How to load (when approved)

**Before anything connects (once).**

1. The 17 tables exist in `HACKFEST0119` and are empty: created by `02_create_tables.sql` (or STEP 2 of `HANA_PREFLIGHT_HACKFEST0119.sql`, which makes the same tables, never both) and STEP 3 of the pre-flight was all `OK`. The loader creates nothing itself.
2. The SAP drivers are installed in the Python that runs the loader: `py -3.12 -m pip install hdbcli sqlalchemy-hana` (both are listed in `requirements-sap.txt`). The loader says so if they are missing.
3. The connection. `--execute` and `--check-target` read it from `DATABASE_URL` (or a bound HANA instance on BTP), so nothing goes on the command line. It needs four things from your HANA Cloud instance: **host** (`<instance-id>.hana.<region>.hanacloud.ondemand.com`), **port** (443), **database user** and **password**. TLS is mandatory (`encrypt=true`). In PowerShell, this prompts without echoing the password, encodes it (a raw `@ : / # %` would break the URL) and keeps it out of your command history and the process list:

```powershell
$u  = Read-Host "HANA user"
$p  = Read-Host "HANA password" -AsSecureString
$pw = [System.Net.NetworkCredential]::new("", $p).Password
$env:DATABASE_URL = "hana+hdbcli://$([uri]::EscapeDataString($u)):$([uri]::EscapeDataString($pw))@<HOST>:443?encrypt=true&sslValidateCertificate=true"
Remove-Variable pw, p
```

   The `DATABASE_URL` in the project's `.env` is a SQLite file and nothing loads `.env` for you, so it is ignored. A SQLite target is refused. The variable lives only in that PowerShell window.

**What command 3 does to `HACKFEST0119`.**

1. Connects, then `SET SCHEMA "HACKFEST0119"`. It stops if the session is not in that schema.
2. Looks before writing: every one of the 17 tables must exist with the model's number of columns and must be **empty**. Otherwise it writes nothing and says which table is the problem.
3. Inserts each CSV in the table order above (parents first), typed exactly as the file holds it, in batches of 5,000, **one transaction per table**: a failure rolls back that table and stops, earlier tables stay.
4. Reads every row count back from HANA with `COUNT(*)` and compares it with the CSV. Every table must say `PASS`.
5. With `--validate`, runs the 190 checks of `03_validate.sql`. Every `OUTCOME` must be `PASS`; the `WARN` rows must match their `EXPECTED` counts.

It never creates, drops, truncates or deletes unless you add `--create` or `--truncate` yourself, which this path does not use. If a load stops part-way, fix the cause and add `--resume`: tables that already hold exactly their expected rows are left alone, the empty ones are loaded, and any other table stops the run untouched.

Alternatively the Database Explorer import wizard, table by table in the order above: the CSVs are UTF-8 with a header row, empty field = NULL, booleans `True`/`False`, dates `YYYY-MM-DD`, timestamps `YYYY-MM-DD HH:MM:SS`. That route has not been tried; the script converts every value to a typed Python value itself.

To try the whole load locally first: `py -3.12 scripts/load_hana_core.py --rehearse` (create, load and validate in an in-memory SQLite database; it connects to nothing).

## Validation

`03_validate.sql` has 10 groups: row counts, NULL primary keys, duplicate primary keys (including the demand, inventory and supplier-product keys), orphan foreign keys (the 20 declared plus the relationships that are deliberately not foreign keys), invalid provenance, invalid dates, negative quantities and ranges (every CHECK constraint restated as a query), tariff ranges, cross-table consistency, and control totals summed from the CSVs.

## Decisions that need your approval before loading

1. **Target schema and privileges.** The schema is confirmed as HACKFEST0119. `01_create_tables.sql` stays unqualified (it lands in the current schema). Whether your user may create tables there is what `HANA_PREFLIGHT_HACKFEST0119.sql` tests first.
2. **DECIMAL for fixed-decimal measures.** Costs, distances, coordinates and shares are DECIMAL so they stay exact; HANA returns them as `Decimal`, while the application's `ref_*` contract expects floats, so any `REF_*` view must `CAST(... AS DOUBLE)`.
3. **`PRODUCT.AVG_UNIT_PRICE_GBP` is DOUBLE.** 12 of its 3,798 values carry floating-point noise (more than 4 decimals, e.g. 8.379999999999999). Rounding them would change the cleaned data, which was not to be modified. Accept DOUBLE, or approve a fix in the cleaned layer.
4. **`DEMAND_MODELING_PANEL` keeps all 18 columns**, including the ML lag and rolling features; the application reads 6 of them.
5. **CHECK constraints beyond provenance and non-negativity.** Vocabularies (risk levels, statuses, transport modes, scenario types) come from the codebase and ranges from the data's meaning. They can reject future data that uses a new value; each is one line in `hana_core_spec.py`.
6. **One provenance CHECK for every table** (REAL, DERIVED, SYNTHETIC, AUTHORED), not a narrower set per table. The validation warns when a table holds a label other than the one it was cleaned with.
7. **20 foreign keys, enforced.** Deliberately not foreign keys: `DEMAND` and `DEMAND_MODELING_PANEL`.`LOCATION_ID` (a text label; the key would have to be the nullable, non-unique `COUNTRY.RETAIL_LABEL`), the polymorphic `ENTITY_ID` columns, `TARIFF.DEST_ISO3` (the sentinel `ANY`) and `PORT.COUNTRY_ISO2`. The panel has no ISO-3 column; adding one would change the cleaned data.
8. **Quoted upper-case identifiers**, so `"DATE"` and `"MONTH"` cannot collide with keywords.
9. **An empty CSV field becomes NULL**, which turns `ROUTE.CHOKEPOINTS` for the rail and air lanes from an empty string into NULL.
10. **Table names follow your list**, not the earlier proposal (`DEMAND`, `INVENTORY`, `DEMAND_MODELING_PANEL`), so none of the application's existing `REF_*` tables or views exists yet.
11. **Capacity and cost have no unit.** `CAPACITY` has no time basis and costs are abstract cost units; the model states neither and invents neither.
12. **Nothing has run on HANA.** `CREATE COLUMN TABLE`, CHECK and FOREIGN KEY constraint syntax, `COMMENT ON`, `TO_DATE`, `MONTH` and `ADD_DAYS` are written from HANA's documented syntax and untested against a tenant.
